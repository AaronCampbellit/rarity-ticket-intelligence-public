# Guiding Philosophy

**Status:** Draft

Rarity should feel powerful without feeling complicated. The interface presents the smallest useful surface for each role, while the underlying platform remains consistent and capable.

## Progressive complexity

A new technician primarily sees My Work, New Work, Search, and a relevant dashboard. Queue management, approvals, dependency analysis, automation, integrations, and administration appear as permissions and responsibilities grow.

## Layered protection

No single mistake should become a disaster. Mutations pass through authentication, authorization, validation, workflow rules, business invariants, rate and resource limits, audit, eventing, and recovery mechanisms.

## Operational self-awareness

Rarity continuously understands service health, worker backlog, event lag, integration failures, email delay, automation failures, replication, backup success, storage capacity, and response-time degradation.

## Coherence

Users should learn a small set of concepts once: objects, relationships, work records, ownership, workflows, permissions, timelines, and search. New modules reuse them.
